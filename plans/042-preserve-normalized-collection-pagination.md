## Why this matters

The application RPC list response `{ data, page, limit, total }` is converted
to `CollectionResult` by the Hono helper before it reaches canonical Table.
Table then runs the installed data adapter, whose current implementation only
reads metadata from the top-level backend envelope. It replaces the Hono
helper's nested `meta` with undefined values, so `Table` receives no
`meta.totalPage` and cannot render or bound server pagination. Normalization
must be idempotent: a valid `{ data, meta }` result keeps its metadata and
derives the total page count when enough metadata is available.

## Current state

- `packages/is-vue-framework/src/hono/resource.ts` maps Hono RPC responses to
  framework `CollectionResult` objects.
- `packages/is-vue-framework/src/adapters/projectAdapters.ts` supplies the
  reusable fallback data normalizer used by Table when no app adapter exists.
- `apps/web/src/framework/adapters/data/normalize.ts` is the active web data
  adapter installed from `apps/web/src/framework/adapters/bundle.ts`.
- `packages/is-vue-framework/src/components/core/Table.vue` owns server
  pagination and reads only `loaded.data.value?.meta?.totalPage`; it must stay
  unchanged.

`packages/is-vue-framework/src/hono/resource.ts:127-130` currently loses the
derived page count:

```ts
function normalizeCollection(value: unknown): CollectionResult<object> {
  const response = value as { data: object[]; page?: number; limit?: number; total?: number }
  return { data: response.data, meta: { page: response.page, pageSize: response.limit, total: response.total } }
}
```

`apps/web/src/framework/adapters/data/normalize.ts:15-31` then reads only
top-level pagination fields, even if its payload is already a
`CollectionResult`:

```ts
const total = typeof payload.total === 'number' ? payload.total : undefined
const pageSize = typeof payload.limit === 'number' ? payload.limit : undefined
// returns new metadata from only those values
```

Follow the existing Vitest style in
`packages/is-vue-framework/src/adapters/__tests__/projectAdapters.spec.ts` and
`packages/is-vue-framework/src/hono/__tests__/resource.spec.ts`: direct
assertions of complete result objects, no snapshots. The project uses pnpm and
the package scripts listed below.

## Steps

### Step 1: Make normalized collection metadata canonical in the framework

In `projectAdapters.ts`, recognize a nested `meta` object on a payload with a
`data` array. Copy only numeric `total`, `page`, `pageSize`, and `totalPage`
values. If `totalPage` is absent but `total` and a positive `pageSize` exist,
derive `Math.ceil(total / pageSize)`. Preserve bare arrays and raw top-level
envelopes exactly as today. Add tests showing the default adapter preserves a
pre-normalized result and derives `totalPage`.

**Verify**: run the focused framework tests; adapter tests pass.

### Step 2: Return complete pagination metadata from the Hono resource helper

Update `normalizeCollection` in `hono/resource.ts` to include
`totalPage = Math.ceil(total / limit)` when `total` is numeric and `limit` is a
positive number. Do not manufacture metadata for non-paginated endpoints.
Update the existing Hono resource assertion to include `totalPage: 1`.

**Verify**: run the focused framework tests; Hono resource test passes.

### Step 3: Make the web adapter idempotent and prove the actual regression

Update `apps/web/src/framework/adapters/data/normalize.ts` to accept both raw
web envelopes and framework `CollectionResult` inputs. For nested metadata,
preserve declared numeric `totalPage` or derive it from numeric `total` and a
positive `pageSize`; do not overwrite it with undefined fields. Add
`normalize.spec.ts` beside the adapter with tests for:

- raw `{ data, page: 1, limit: 10, total: 1 }` producing `totalPage: 1`;
- `{ data, meta: { page: 1, pageSize: 10, total: 1 } }` producing
  `totalPage: 1`;
- a declared `meta.totalPage` taking precedence.

Add a core Table test using a normalized `{ data, meta }` load result and
asserting `1 / 2`, proving the default framework path does not erase metadata.

**Verify**: run both focused test commands; all selected tests pass.

`CollectionResult`; data adapters must tolerate both without losing metadata.
