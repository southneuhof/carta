## Why this matters

The router currently has no catch-all route. Arbitrary and legacy-prefixed URLs resolve with no matched component, and the app test command fails two existing assertions. This plan restores the behavior already specified by the router tests and gives all later plans a green test baseline.

## Current state

- `apps/web/src/router/index.ts` installs only generated file routes:

  ```ts
  // apps/web/src/router/index.ts:5-8

    history: createWebHashHistory(),
    routes,
  })
  ```

- `apps/web/src/router/__tests__/routes.spec.ts:17-23` expects arbitrary and legacy paths to resolve as `not-found`, but there is no catch-all file under `apps/web/src/routes/`.
- File routing is configured in `apps/web/vite.config.ts:12-16` with `routesFolder: 'src/routes'` and extensions `.route.vue`/`.layout.vue`.
- Route components use `definePage` to supply stable names; see `apps/web/src/routes/(authenticated)/dashboard/index.route.vue:1-5`.
- Baseline on 2026-07-12: `pnpm --filter @southneuhof/framework-web test` reports 23 passing and 2 failing tests, both in `routes.spec.ts`. Type-check passes.

## Steps

### Step 1: Add the file-routed catch-all page

Create `apps/web/src/routes/[...path].route.vue`, using the Vue Router file-routing catch-all filename and `definePage({ name: 'not-found', meta: { title: 'Page Not Found' } })`. Render a small semantic 404 state with a heading, explanatory copy, and an internal link back to `/`. Reuse existing Tailwind design tokens such as `bg-background`, `text-on-surface`, `text-muted`, and `text-primary`; do not add a new design system or dependency.

The page must live at the route root rather than inside `(public)` or `(authenticated)` so both anonymous and authenticated unknown URLs resolve consistently.

**Verify**: `pnpm --filter @southneuhof/framework-web test -- router/__tests__/routes.spec.ts` -> all tests in `routes.spec.ts` pass and there are no "No match found" warnings for the asserted paths.

### Step 2: Strengthen route assertions without changing intent

Retain the existing assertions for `/missing/deep`, `/authenticated/settings/users`, and `/unauthenticated/auth/login`. Add assertions that the catch-all has at least one matched route record and that known routes such as `/settings/users` still win over the catch-all. Do not replace the existing route-name assertions with snapshots.

**Verify**: `pnpm --filter @southneuhof/framework-web test -- router/__tests__/routes.spec.ts` -> all focused tests pass.
